# Kith prototype: flow, UI and design-system audit

**Date:** 2026-11-10 · **Branch:** `glass-ui-home-onboarding` · **Viewport tested:** 375×812 (mobile)
**Walked:** Home → Scan (360°) → Onboarding 01–05 → Editor identification (fixed → movable) → Start fresh → Redesign editor → More menu → AI prompt
**Lenses:** 10 usability heuristics, `craft` / `better-ui` / `better-typography` / `better-accessibility`

> ⚠️ **Verdict: several issues to address.** The bones are good: one glass language over the room, a tight 5-step onboarding, pills that cut typing. The problems are (1) the documented design system no longer describes the app, (2) one broken motion token silently disables every entry animation, (3) the editor's identification steps rely on toasts to explain themselves, and (4) destructive "clear" actions have three names and inconsistent safety.

---

## 1. Design system: what's documented vs. what ships

| Topic | `design-system/kith-spatial-design/MASTER.md` | `PROTOTYPE.md` | Actual code |
|---|---|---|---|
| Typeface | Cinzel + Josefin Sans | – | **Inter** (`index.html`, `tailwind.config.cjs`) |
| Palette | Warm grey `#78716C` + amber CTA `#D97706` | – | **Neutral gluestack** greys, near-black primary (`global.css`) |
| Style | Minimalism / Swiss, scroll storytelling landing page | – | Mobile app, clear + frosted glass over a room |
| Sheets/dialogs | White modal, 16px radius | "**frosted white** glass" | **Dark** frosted glass (`.k-panel`, `.k-panel-strong`) |
| Token location | CSS vars `--color-*` | `src/design/tokens.css`, `components.css` | Those files **don't exist**. Tokens live in `src/global.css` + `src/components/glass.ts` |

**Finding DS-1 (high):** MASTER.md is a generator output for a different product (real-estate landing page). Any agent or designer following it will push the app *away* from what's built. → Rewrite MASTER.md from the code.

**Finding DS-2 (high, bug):** `.animate-in` uses `var(--k-spring)`, which is never defined. An undefined var makes the whole `animation` declaration invalid, so **every `animate-in` entry (toasts, sheets, popups, steps, chips) snaps in with no motion**, contrary to the "no instant state changes" rule.

**Finding DS-3 (medium):** Radius has no scale. Counted in screens/editor: `rounded-full` ×121, `xl` ×14, `2xl` ×12, `3xl` ×6, `md` ×4, `lg` ×4, plus Badge `rounded-sm` and Textarea `rounded` (4px). Badges are the only square-cornered chip in an all-pill UI.

**Finding DS-4 (medium):** Badge text is forced `uppercase`. Every other label is sentence case, so "WHOLE ROOM", "DETECTED FROM YOUR SCAN", "MOVE · ADD · REARRANGE" read as a different system. The icon also sits flush against the text (no gap).

**Finding DS-5 (low):** Hard-coded hex colors in `AIScenarioSheet.tsx` and `AssetsDrawer.tsx` (amber/brown/slate ×40+), plus raw `bg-sky-400` / `bg-emerald-400` status dots in the layers modal. They're content swatches mostly, but the status dots should be tokens.

**Finding DS-6 (low):** `theme-color` is `#F3F4F7` while the app background is `#FFFFFF` (status bar seam on Android).

## 2. Flow findings (heuristics)

**H1 · Visibility of system status**
- Editor identification step 1 (fixed items) has **no title or instruction**: only a 2-dot indicator, "7 detected", Skip / Confirm. Step 2's instruction ("Verify movable objects") is a toast that disappears after 2.8s.
- Object counts disagree: Home card says **16 objects**, identification shows **7** then **9 detected**, and the editor snackbar hard-codes **"8 objects detected"**.

**H2 · Match with the real world**
- Menu copy is internal: "Reset Walkthrough", "Cycle Lighting (natural daylight)" (raw enum text), "Spatial Elements", "Wireframe Ghost / Solid Model", "Kith AI synthesizing layout…".
- The same action has three names: **Clear Canvas** (pill), **Clear the room** (popup), **Clear Room (Keep Fixtures)** (menu). Restore is **Restore Canvas** / **Restore Original Layout**.

**H3 · User control and freedom**
- Menu "Clear Room (Keep Fixtures)" fires instantly with no confirmation, while the pill path asks first.
- Menu "Reset Walkthrough" wipes scenario state with no undo.

**H4 · Consistency and standards**
- **Confirm** means "this detection list is right" in identification step 1, then "place my staged moves" in the top bar. Step 2 of the same 2-step flow uses **Next**.
- Title Case ("Keep Current", "Return to Home Screen", "Start New 360° Scan") vs sentence case everywhere else.
- Icons: `Smartphone` stands for Home, and `Sparkles` is reused for AI, new scan *and* lighting.
- "Return to Home Screen" duplicates the Home button in the top bar.

**H5 · Error prevention**
- The Start-fresh popup makes the destructive **Clear the room** the filled primary button, and it's the first thing shown after identification. The prototype's core test is *moving existing furniture*, so the safe default should be keeping it.
- Onboarding pre-fills "Aarav's Room", the same name as the existing project on Home (two identical cards after one run).

**H6 · Recognition over recall**
- The canvas never says "Hold a piece to move it" once you land on it. The only hint is a snackbar that `openEditor()` turns off.

**H8 · Aesthetic and minimalist design**
- Onboarding step 3: the description textarea is fixed at `h-36` while its content grows, so text spills under the "What do you do here?" label. The textarea also renders at 16px next to 13–14px labels.
- The More menu's destructive row is a large red pill that dominates a utility list.

**Accessibility (WCAG 2.1/2.2)**
- `index.html` sets `maximum-scale=1, user-scalable=no`, which blocks pinch-zoom (1.4.4 Resize text).
- The Scan shutter and onboarding Continue render as generic `div`s without a button role (4.1.2 Name, Role, Value).

## 3. Biggest gap (not fixed here, needs a product decision)

**The editor is a procedural 3D room, not the 360° photo.** The user scans a real, photo-real room with red curtains, then lands in a CG room that looks different, while PROTOTYPE.md says "the user lands in a 360° view of the sample room". For a Wizard-of-Oz test whose whole point is "dragging furniture around a 360° photo", that break in continuity is the highest-risk validity issue. Options: map the equirectangular panorama onto the room box as the base layer, or at least crossfade from the photo into the 3D room during processing so it reads as the "room box".

### Found while verifying
- Once `--k-spring` worked, the `k-in` keyframe's `transform: none` end state overrode Tailwind's `-translate-x-1/2`, so centered toasts and hints slid off-center. The keyframe now animates the individual `translate`/`scale` properties.
- Onboarding step 3: the Room type, Description and activity groups were all flex-shrunk below their content (RN-web gives views `min-height: 0`), so they overlapped. Pinned with `shrink-0`.
- Undo now covers "Start the scenario over" (the old "Reset walkthrough" wiped history).

## 6. Third pass (skills: `apple-design`, `better-interface`, `state-machine`, `break`, `beautiful-shadows`)

### Ghost shapes and sizes (requested)
| Ghost | Was | Now | Files |
|---|---|---|---|
| Staging ghost (hold / drag / waiting for Confirm) | One generic primitive per "kind": hamper = plain tapered cylinder, desk = slab + 4 legs | Built from the piece's own meshes in the ghost material, centred on its measured box, so size and silhouette match the furniture (rim, mirror, legs, contents). Pick volume, wall-snap faces, shadow and arrow unchanged; falls back to the primitive if a model has no meshes | `utils/stagingProxy.ts` (`buildStagingProxyFromObject`), `editor/PanoramicViewer.tsx` |
| Step-5 AI ghost brackets | Hand-typed sizes centred on the group origin: fan box `0.6×1.5×0.6` sat half under the floor; dressing table ignored where the mirror is | Measured from the group's meshes; brackets sit on the real extents with a 2.5cm pad and arm length scaled to the piece | `utils/proceduralRoom3D.ts` (`addCornerBrackets`) |

Verified in the browser: hamper and dressing-table ghosts while holding and after dropping. Step-5 brackets verified in code only (that scripted step isn't reachable by automation).

### apple-design
- **Wall snap glides instead of teleporting.** The held ghost follows its target with a critically damped glide (τ 45ms): ordinary tracking stays 1:1, the up-to-22cm snap jump becomes continuous. Confirm still uses the exact logical position.
- **Press feedback on pointer-down:** every Button scales to 0.96 over 150ms ease-out while pressed, never when disabled.
- **Size-specific tracking and leading** on headings (−0.03em/1.05 at 5xl down to −0.015em at lg).
- **Reduced motion** keeps entrances as short cross-fades (no slide/scale) instead of removing feedback; **reduced transparency** turns glass solid; **more contrast** gives glass a near-solid fill and a clear edge.

### better-interface (scope: the Redesign editor canvas, 375px and 320px)
| Severity | Location | Before | After | Why |
|---|---|---|---|---|
| HIGH | `App.tsx` move hint | Sat in the top band, covering Undo and the 360° button | Sits above Clear room, full gutter width | Controls hidden behind an overlay |
| HIGH | `editor/MobileTopBar.tsx` | At 320px with a move pending, Home (x30–76) overlapped Discard (x49–103) | More options hidden while moves wait (Confirm/Discard is the only decision): bar needs 305px, not 371px | Overlapping controls at 320px |
